# Critical scenarios

Use these as conceptual forward-tests after changing the skill or when a request resembles them. The expected behavior is a decision test, not a layout recipe.

## A — Search-first intent

Given a page whose meaningful job is searching, the agent should identify search as dominant, remove or subordinate unrelated promotion/navigation, make query feedback and results predictable, and avoid adding decorative sections merely to fill space.

## B — High-density product decision

Given a product page with price, condition, seller, delivery, protection, specifications and reviews, the agent should preserve decision-critical evidence, group it by decision stage, make purchase action and trust legible, and use progressive disclosure for depth. It must not equate minimalism with hiding information.

## C — Dashboard overload

Given many indicators, the agent should ask what each enables the user to decide or diagnose, prioritize situation → exception → diagnosis → action, and recommend removing or demoting metrics with no actionable purpose.

## D — Ready-to-buy landing page

Given a commercial visitor with high purchase readiness, the agent should expose the direct action early, provide enough value/trust to act, and place deeper proof, explanation and objections where they support uncertainty. It should not force a cinematic narrative or fake scarcity.

## E — Existing repository redesign

Given a redesign request, the agent should inspect framework, routes, design system, shared components, behavior and impacted rules before editing. It should reuse conventions, identify blast radius, prioritize behavioral findings and validate the actual flow at responsive sizes.

A response that jumps to “modern hero,” “more cards,” “more whitespace,” “gradient,” or “add animation” without first establishing intent, hierarchy and evidence fails these tests.
